**Интерактивная демонстрация (публичная, без SSH):** https://musikfed.github.io/view_my_prj/pitools/

**Общая галерея:** https://musikfed.github.io/view_my_prj/

**Исходные материалы:** `pitools.py`, `pitools.prj`, `РЕФЕРАТ.pdf` и свидетельство регистрации, размещённые в этом репозитории.

## Назначение

Программа для автоматизированного параллельного деплоя файлов на несколько SSH-серверов через интерпретацию файлов .prj. Регистрация программы для ЭВМ № **2026610793** от **15.01.2026**, номер заявки **2025698382** от 29.12.2025. Автор: Герасимов Федор Анатольевич.

Текущий образец `pitools.prj`:

```text
MLT: test.server.ru
PRJ: /tmp/test
FL: test.txt
```

Запуск локальной CLI-программы в инфраструктуре пользователя:

```bash
python3 pitools.py pitools.prj --key ~/.ssh/id_rsa --user deploy
```

В представленном репозитории **нет `test.txt`** — реальная отправка образца требует предварительного создания такого файла. Веб-презентация **никогда не выполняет** эту команду, не принимает SSH-ключи, не подключается к серверам и не создаёт на них файлы.

## Проверенный по исходникам поток

1. `parse_prj()`: читает строки, отбрасывает комментарии и с помощью `shlex.split` собирает блоки `MLT:`, `PRJ:`, `FL:`.
2. `deploy()`: по каждому файлу данного блока создаёт задачи `fl_deploy()` для всех хостов и ожидает их параллельно через `asyncio.gather`.
3. `fl_deploy()`: `Paramiko.SSHClient`, авторизация SSH-ключом, `open_sftp()`, создание родительского каталога целевого пути, `sftp.put`, `chmod(0o644)`.
4. `verify_deployed_files()`: только после некоторого успеха отправки запускается для `block['hosts'][0]`, а не для каждого хоста.

## Фактические ограничения, выявленные при чтении версии v6.1

Эти различия между описанием и реализацией **не скрываются** публичной презентацией:

- Для `PRJ: /tmp/test` каталогом становится `Path(target).parent` → `/tmp`, имя загруженного файла `host_prefix + '_' + Path(target).name` → `/tmp/test_test` при первом хосте.
- Контроль использует другое имя: `host_prefix + '_' + filename` → `test_test.txt`. Команда `sha256sum` исполняется **без абсолютного пути**. Это не тот же файл, что был передан, если не вмешиваются посторонние файлы/окружение.
- Проверка выполняется лишь на первом хосте блока, а её статус не агрегируется в итог деплоя.
- Вызов `verify_integrity()` закомментирован; наличие функции и `checksum.txt` в описании не означает включённую самопроверку.
- `AutoAddPolicy()` автоматически принимает неизвестные SSH host keys; ограничителя целевых директорий в `deploy()` нет.
- В изображении свидетельства указан объём **9141 байт**, и предоставленный для анализа пользователем `pitools.py` тоже содержит **9141 байт**. В реферате (28.12.2025) указан другой объём — **9434 байта**. Совпадение размера со свидетельством не доказывает побайтовую идентичность зарегистрированному экземпляру.

Ни одна из этих проблем **не исправлена** в исходной программе при разработке веб-презентации. Демонстрация не выдаёт смоделированную передачу за настоящий успешный деплой и отдельно маркирует неподтверждённую целостность.

## Принцип визуальной демонстрации

- Параметр «Один сервер» воспроизводит структуру предоставленного `.prj`.
- Параметр «Три сервера» иллюстрирует расширение `MLT:` без фактических подключений.
- Отображаются фазы parse → asyncio.gather → SSH → SFTP mkdir/put/chmod → попытка SHA-256 → сводка.
- 11 языков доступны для элементов управления; подробный аудит кода дан по-русски, английское пояснение этапов доступно при выборе EN.
- Исходники могут меняться. Интерактивная схема описывает проверенную версию, а не гарантию результатов следующего релиза.
